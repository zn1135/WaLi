# 小陀螺模式下云台坐标系轮速设计

## 背景

`Odom.wheel_vx` 和 `Odom.wheel_vy` 当前由四个麦克纳姆轮的编码器速度直接逆解得到，因此天然属于底盘机体系。普通跟随状态下，底盘与云台基本同向，这两个坐标系的差异不明显；小陀螺模式下底盘持续相对云台旋转，底盘纵向分量随相对角周期变化，导致 `Odom.wheel_vy` 无法直接表示驾驶员所期望的“沿云台朝向的前后速度”。

## 目标

- `Odom.wheel_vy` 表示云台坐标系的前后速度。
- `Odom.wheel_vx` 与 `Odom.wheel_vy` 保持为同一坐标系的一对分量，表示云台坐标系的横向和纵向速度。
- 小陀螺模式下，机器人沿云台前向平移时，即使底盘持续旋转，理想无打滑情况下 `Odom.wheel_vy` 仍保持同方向、近似恒定。
- 世界系速度融合、位置积分和底盘航向计算保持原有语义。

## 非目标

- 不修改遥控器或键鼠到底盘速度指令的映射。
- 不修改 `ChassisControl_Calculating()` 的小陀螺运动学正解。
- 不调整轮径、减速比、旋转半径、卡尔曼参数或轮速符号标定值。
- 不试图补偿麦轮打滑、功率限制或机械误差。

## 方案

### 1. 分离内部测量坐标系和公开输出坐标系

四轮编码器逆解首先生成两个函数内局部量：

- `wheel_vx_chassis`：底盘机体系横向速度。
- `wheel_vy_chassis`：底盘机体系纵向速度。

世界系轮速测量继续使用这两个底盘机体系局部量和 `Odom.yaw_chassis` 计算，避免改变卡尔曼融合及位置积分的数据流。

### 2. 将公开轮速转换到云台坐标系

使用与小陀螺控制相同的相对角：

```c
rel = xRelativeAngle.receive_yaw_relative_rad;
```

`ChassisControl_Calculating()` 将云台坐标系指令转换到底盘机体系。里程计采用其严格逆变换，将底盘机体系实测轮速转换回云台坐标系：

```c
Odom.wheel_vx = wheel_vx_chassis * cos(rel)
              - wheel_vy_chassis * sin(rel);

Odom.wheel_vy = wheel_vx_chassis * sin(rel)
              + wheel_vy_chassis * cos(rel);
```

该变换同时处理横向和纵向分量，避免两个公开字段属于不同坐标系。

### 3. 更新接口说明

`Odometry.h` 中 `wheel_vx`、`wheel_vy` 的注释改为云台坐标系。底盘机体系局部量不加入公共结构体，防止增加未使用接口。

## 数据流

```text
四轮编码器反馈
    -> 麦轮逆解（底盘机体系局部量）
        -> 使用底盘航向旋转到世界系
            -> 卡尔曼融合与位置积分（保持现状）
        -> 使用云台—底盘相对角做逆变换
            -> Odom.wheel_vx / Odom.wheel_vy（云台坐标系）
```

## 边界与异常处理

- 相对角使用现有 `[-PI, PI]` 归一化结果；正弦和余弦在边界处连续，不需要额外分支。
- 初始化期间沿用现有相对角数据，不引入新的状态或缓存。
- 轮电机反馈缺失、打滑或饱和仍会反映为测量误差，本次修改不掩盖这些现象。
- 轮速符号继续由 `ODOM_VX_SIGN` 和 `ODOM_VY_SIGN` 标定；坐标旋转不承担符号校准职责。

## 回归测试

测试应覆盖正解后再逆解及坐标还原：

1. 相对角为 `0`：云台与底盘同向，输出等于原底盘机体系速度。
2. 相对角为 `+PI/2`：云台前向平移对应底盘横向分量，恢复后的 `wheel_vy` 仍等于云台前向输入。
3. 相对角为 `-PI/2`：验证相反旋转方向的符号。
4. 平移叠加正向自转：轮速逆解应消除共同旋转分量，恢复云台平移速度。
5. 平移叠加反向自转：验证旋转方向不影响恢复结果。
6. 纯自转：`wheel_vx` 和 `wheel_vy` 均应接近零。

浮点比较使用小容差，不要求逐位相等。

## 验收标准

- 上述运动学回归测试全部通过。
- 固件工程编译无新增错误和警告。
- VOFA 中按云台前向移动时，`Odom.wheel_vy` 的正负方向不随底盘旋转角翻转；停止平移、仅小陀螺旋转时，该值接近零。
- 原有世界系速度、位置积分代码仍使用底盘机体系逆解结果，不使用已经转换为云台坐标系的公开字段。
